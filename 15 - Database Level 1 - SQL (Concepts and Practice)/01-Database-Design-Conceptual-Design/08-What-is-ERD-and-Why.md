# 08 - ERD (Entity Relationship Diagram)

## Overview

This lesson explains ERD (Entity Relationship Diagram) and its role in database design. It shows how ERD represents entities, attributes, and relationships before database implementation.

## Main Topics

### What is ERD?

ERD stands for **Entity Relationship Diagram**.

It is a visual diagram that shows the relationships between entities that will be stored in a database. It is used as a basic structural design for the database.

The three main components are:

* **Entities:** Represent objects or tables.
* **Attributes:** Represent the fields or properties of each entity.
* **Relationships:** Show how entities are connected.

### ER Model

An ER Model represents the structure of a database using diagrams.

ER modeling is a systematic process for designing databases. It requires analyzing the data requirements before starting the actual implementation.

### Why Use ER Diagrams?

ER diagrams help to:

* Visualize the database structure.
* Identify the required fields for each entity.
* Understand the data and information that will be stored.
* Reduce complexity.
* Build tables more easily.
* Preview the logical database structure before implementation.
* Improve communication between users and database developers.

### Conceptual Database Design

ERD is widely used to describe the **Conceptual Design** of databases.

It helps users and database developers review the database structure before implementation.

## Key Takeaways

* ERD stands for Entity Relationship Diagram.
* ERD shows entities, attributes, and relationships.
* ER diagrams help visualize the database structure.
* ER modeling analyzes data requirements before implementation.
* ERD helps reduce complexity in database design.
* ERD improves communication between users and database developers.
